## Key Concepts

### Three Diagrams Answer Three Different Questions

Different diagrams are used to describe different aspects of a system.

Each diagram answers a different question about the same requirement.

### Use Case Diagram

A Use Case Diagram defines who interacts with the system and what they need from it.

It focuses on:

- Actors
- System goals
- User interactions

### Activity Diagram

An Activity Diagram shows how work moves through a process.

It represents:

- Steps
- Decisions
- Flow of actions
- Start and end points

### Class Box

A class box represents a class using three main parts:

- Class name
- State / attributes
- Behavior / methods

Example:

```text
Student
----------------
name
score
----------------
add_score()
average()
```

### Class Diagram

A Class Diagram connects the classes and objects that make up a system.

It shows the structure of the system and the relationships between its classes.

### One Requirement, Three Consistent Views

The same system requirement can be represented using different diagrams:

- **Use Case Diagram** – Who needs what
- **Activity Diagram** – How the process flows
- **Class Diagram** – What objects and relationships are needed

All diagrams should remain consistent with the same system requirement.
